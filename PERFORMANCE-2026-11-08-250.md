# 0.2.50-dev: центр дока и стоимость закрытия

Продолжение `PERFORMANCE-2026-11-08-249.md`. Документ 249 описывает промежуточную реализацию; её перенос дока внутрь экрана отменён.

## Поведение

Док расширяется симметрично относительно центра иконок, без привязки к нижней границе экрана и без ограничения высотой hotseat. `DockLayer` преобразует координаты hotseat в собственные локальные координаты, учитывая фактический отступ слоя в DragLayer. Прежнее преобразование в координаты родителя повторно добавляло отступ. Физический край дисплея по-прежнему ограничивает видимую площадь; увеличение padding не сдвигает иконки или центр пластины.

Материал летящей иконки/группы при открытии удерживается без периодических отправок live-кадров. При закрытии live-блюр обновляется с пределом `min(пользовательский FPS,30)`. Это ограничение материала, а не движения/матриц/радиуса штатной анимации лаунчера. Направление задаётся событиями запуска приложения и возврата/resume; подготовка под пальцем не запускает периодическое обновление.

Сцена мультипапки кэшируется по ID элемента, пользователю и размерам, а не по временной View снимка. При возврате используется подготовленная геометрия и содержимое, но фон в полёте пересэмплируется по текущему положению. Настройки инвалидируют кэш; спокойная отрисовка рабочего стола после срока удержания удаляет старую сцену. Общий бюджет кэша ограничен.

## Проверки на PLZ110 / Android 17 / launcher 17.3.12

Сценарий `folders-flight250`: открыть приложение из вертикальной группы, подождать окончания, вернуться; повторить для второй вертикальной и горизонтальной группы; открыть/закрыть две обычные папки. PID лаунчера сохранился. На записи первой вертикальной группы сохранены формат 1×2 и содержимое, отсутствует переход в квадрат 1×1.

| Событие | Результат |
|---|---:|
| Live-кадры при открытии второй/третьей групп | 0 / 0 |
| Live-кадры при закрытии групп | 23 / 22 / 22 за ~0,75 с |

Это замер операций модуля, не точный FPS всего лаунчера. Полное отсутствие просадок не заявляется. Холодная подготовка сцены при открытии всё ещё требует GPU-снимков: в этом прогоне три построения, максимум 78,955 мс. Ограничение FPS полёта само по себе эту стоимость не устраняет; повторное построение при трёх закрытиях устранено.

32 unit-теста, `assembleRelease` и `lintRelease` проходят. Изолированные проверки настоящего APK на телефоне: сохранность hardware bitmap после recycle; вертикальная сцена после замены Bitmap внутри Drawable; software Canvas; фон при foreign draw без готового sampler; отсутствие повторной записи статичного дока при 20 native-трансформациях. Также выполнены повторная разблокировка и быстрое чередование приложений.
