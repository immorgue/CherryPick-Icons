# 0.2.63-dev: папки, удержание, навигация и профили обоев

## Контуры папок

Проверка на устройстве выявила две ошибки первоначального кандидата: квадратный
Outline от ColorDrawable ошибочно использовался как готовый контур; после его
исключения обычный clip давал слишком сильное закругление по сравнению с нативным
блюром. Значение mRadius само по себе не описывает тип и вес GPU-закругления.

Для фоновой папки теперь считываются mHostType, mCornerType и mCornerWeight
из mDefaultDrawable настоящего OEM-производителя до его освобождения.
Геометрический GradientDrawableWrapper с этими параметрами строит контур,
включая нативную компенсацию радиуса. Его mStrokePath здесь нельзя объявлять
«неправильным» только по названию: на устройстве прежняя замена на общий clip
изменила форму. Нативный контроллер после чтения политики немедленно recycle(),
и в latest сам recycle() снимает MaterialBlurAnimHelper-подписку; старый
unRegisterBlurTransitionAnim вызывается только при наличии метода.
Постоянный второй производитель блюра не сохраняется.

При отсутствии политики остаются clip владельца и доступная геометрия drawable.
Прямоугольный Outline без положительного радиуса не считается контуром папки.
У мультипапок GridRecyclerView используется собственный нативный clip,
пересечённый с доступным контуром заливки. Тот же путь участвует в переходе.

Локально разобраны все шесть APK (пять уникальных):

| Семейство | Нативный clip GridRecyclerView | Контур заливки | GlassDrawable |
|---|---|---|---|
| ColorOS 17 Global | SmoothRoundedManager | SmoothRoundDrawable.mPath | нет |
| Realme UI 16 China | legacy OplusPath | SmoothRoundDrawable.mPath | нет |
| OxygenOS 16 | legacy OplusPath | SmoothRoundDrawable.mPath | нет |
| ColorOS 17.3 China | SmoothRoundedManager | SmoothRoundDrawable.mPath | нет |
| OxygenOS 17.5 / COS17 latest | SmoothRoundedManager | SmoothRoundDrawable.mPath | backgroundDrawable |

Два APK 17.5 идентичны по SHA-256. В latest действительно есть дополнительное
нативное оформление GlassDrawable и ветка getNormalDrawable для Bplus stroke.
Она зависит от конфигурации прошивки/темы. Наличие класса не доказывает, что
именно этот режим активен у автора скриншота; совпадение картинки нужно проверить
на соответствующей прошивке. Аудит не устанавливает другой лаунчер на телефон.

## Удержание и перенос

Ранее поднятый элемент мог переключаться с обоев/материала родителя на отдельный
захват сцены из RenderNode. Это меняет вход блюра и способно резко менять его вид.
Захват сцены перенесён в developer-переключатель
`experimental_scene_drag_backdrop`, по умолчанию OFF.
Обычный drag preview передаёт контекст исходного элемента: иконки продолжают
получать материал дока/папки после переноса в DragView. Хранятся слабые ссылки;
повторное размытие сцены не требуется. Исходный родитель допускается временно
скрытым, как это делает OEM при поднятии элемента. Обычная отрисовка скрытые
подложки по-прежнему не выбирает.

## Интерфейс

- Три постоянные вкладки: Главная, Модуль, Настройки. Нижняя плавающая пилюля
  не уезжает вместе с контентом; под неё зарезервирован отступ прокрутки.
- Главная: статус LSPosed/модуля, основной выключатель, перезапуск, информация.
- Модуль: категории с названием и описанием, сгруппированные по оформлению,
  рабочему столу и работе модуля. Цвета, блюр, иконки, папки, док, виджеты,
  рабочий стол, обои и обновление блюра открывают отдельные экраны.
- Настройки: язык, переход к разработчику, запуск, импорт/экспорт и ZIP-репорт.
- История навигации сохраняется при пересоздании Activity. Back сначала
  возвращает предыдущий экран; выход возможен только при пустой истории.
  Положение прокрутки сохраняется при переходах внутри Activity.
- Переход: короткое смещение и crossfade, 280 мс на входе / 180 мс на выходе.
  Отключённые системные анимации учитываются. Настройки материала не сбрасываются.

## Профили обоев

Функция включается отдельно в Модуль → Обои, по умолчанию OFF. Лаунчер определяет
статичные обои по SHA-256 файла вне UI-потока при старте и ACTION_WALLPAPER_CHANGED.
У всех шести APK заявлено READ_WALLPAPER_INTERNAL; фактическое разрешение проверяется
в процессе лаунчера. Если чтение запрещено или обои меняются во время чтения,
профиль не переключается по предположительному ID.

Перед переходом сохраняется оформление прежних обоев, затем восстанавливается
знакомый профиль. Новые обои наследуют текущий вид. Профили хранятся отдельно от
обычных настроек; сетка/размеры рабочего стола, язык, включение модуля и настройки
разработчика не восстанавливаются из профиля. Отсутствие scoped-ключа сохраняет
его смысл «наследовать». Есть ручное сохранение текущего оформления.

Живые обои идентифицируются по сервису и ID текущей установки. Один сервис может
содержать разные видео: связывать их только по имени пакета было бы ошибкой.
Поэтому повторная установка видео пока не гарантирует узнавание прежнего профиля.

до 13 групп на всех шести APK; 36 отрицательных проверок обнаруживают удалённые

## Продолжение на устройстве 10 ноября

Подключённый лаунчер обновлён до 17.5.4 (170050004). SHA-256 установленного APK
совпадает с COS17 latest из набора. Проверены вкладки, категория папок, Back-жест,
раздел обоев, удержание элемента иконки, дока, папки и длинного элемента без
нажатий на удаление/перегруппировку. Настройки до и после сравнены: старые ключи
не изменены. GPU-тест дополнен отказом от прямоугольного контура ColorDrawable;
проходят также родительские подложки и восстановление bounds drawable.

Для карусели найден реальный источник: InspirationThemeData системного приложения
com.oplus.wallpapers. Локально прочитаны его БД, APK и миниатюры. Каталог состоит
из сохранённых системных тем, а не произвольных картинок. Активная определяется
по inUse. Запись OEM-БД не используется. Новый ThemeCatalog читает ограниченные
снимки БД и миниатюры через root в рабочем потоке; на неподдерживаемой прошивке
используются публичный системный выбор обоев и доступные live-сервисы Android. Карусель следует видео-референсу 00:12:39:
центральная карточка и уменьшенные соседи, настройки выбранной неактивной темы,
копирование её сохранённого оформления. Перезапуск лаунчера закреплён на всех
экранах вкладки Модуль.

Кнопка применения передаёт родной Parcelable с ID темы системному ThemeEditActivity
через штатный activity-manager запуск с from_type=3. Системный редактор сам
загружает полную тему по ID; финальное применение остаётся его кнопке Apply.
Изображение через WallpaperManager.setBitmap не подменяется.

Пользователь сообщил, что при свайпе отстаёт блюр папок и иконок. Эта регрессия
остаётся открытой: по его указанию сначала завершаются радиусы и карусель, затем
исследуется компенсация свайпа отдельно от закрытия/разблокировки. В 0.2.62 была
удалена слишком широко действовавшая экстраполяция crop; это возможный фактор,
но причинность и окончательное исправление пока не подтверждены.
